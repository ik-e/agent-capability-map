# 서울 R0 실행 파일럿

## 2026년 11월 1일 결과

v2의 6과제×3조건 18회가 완료되었다. [결과 보고서](../../docs/seoul-discovery-pilot-2026-11-01.md)와 [공개 집계](r0-v2-summary.json)는 시간·CLI 입력/캐시/비캐시/출력을 구분한다. 정본 변경 없이 실행했고 R1은 미실시다. 전체적으로 지도 조건의 시간·토큰 우위를 확인하지 못했으며, 후보 발견을 실제 데이터 확보·작업 완료로 채점하지 않았다.

**외부 예산 계측 정정:** CLI가 batch 요청을 대표 동작 하나로 요약하므로 `summarize_r0_pilot.py`의 `observed_web_budget_units`는 원자 조회 수의 하한이다. `over_web_budget=false`는 20회 준수 증거가 아니다. `audit_r0_budget.py`가 18회 모두의 batch 축약 근거와 미계측 판정을 별도 파일에 남긴다. 잠긴 원본 summary는 수정하지 않았다. 다음 실행은 원래 도구 인자에서 query/open/find/click을 실행 전 계수해야 한다.

`export_r0_pilot.py`는 잠긴 원시 결과의 해시를 검증한 뒤 공개 가능한 수치만 내보낸다. 원시 실행·웹 대화와 사후 검토는 Git 제외 경로에 보존한다. `prepare_r0_review.py`는 여섯 제공자에 담당 과제의 세 답변을 나누어 검토할 패킷을 만든다. 외부 검토는 재실행·독립 정답표를 대체하지 않는다.

## 실행 환경 수정 기록

v1은 실제 시행 중 Windows 읽기 전용 CLI의 파일 읽기 차단이 발견되어 중단했다. 6개 완료 시행과 1개 중단 시행을 진단 기록으로만 보존한다. 지도 조건이 카탈로그를 제대로 읽지 못했으므로 효용 비교에 사용하지 않는다.

v2는 `run_r0_pilot_v2.py`로 별도 잠근다. `pilot_catalog_mcp.mjs`는 동결 카탈로그의 manifest/browse/search/detail만 읽는 **시험 하네스용** stdio MCP이며 외부 실행·네트워크·인증정보 기능이 없다. 모든 조건에 같은 도구 스키마를 제공하고 B/C에서는 카탈로그 접근을 거부한다. 실제 모델이 manifest를 호출해 리비전과 정보원 0건을 읽는 환경 보정 검사를 먼저 통과했다. 어댑터 바이트 수·조회 시각·도구 호출도 기록한다. 이는 공개 제품 MCP를 출시한 변경이 아니다.

v1과 v2의 결과는 합산하지 않는다. 같은 개발용 과제를 재실행하므로 미사용 holdout이라고 주장하지 않는다. v2의 과제·정본은 기존과 같지만 접근 경로가 달라 신규 protocol hash를 기록한다. 시각적 UI·HTTP 응답 지연에 대한 한계는 그대로다.

`r0-tasks.json`은 정보원·도구·보류의 서로 다른 정보 요구 6개이며, 같은 모델의 새 문맥에서 A/B/C 조건을 비교한다. `result.schema.json`은 답변 형식 계약이다. `scripts/run_r0_pilot.py --freeze`가 과제·예산·모델·실행순서·스냅샷 해시를 고정하고 `--run`은 미실행 항목을 순서대로 수행한다. 원문 실행 로그와 답변은 Git에서 제외된 `evals/runs/`에 둔다. 결과를 다른 시행의 입력으로 공유하지 않는다.

2026-11-01 v1은 `gpt-6.1-sol`, medium, 새 CLI 문맥, read-only sandbox, 동일 웹 검색 도구를 사용한다. 지도 조건은 GitHub Pages 배포본과 같은 동결된 정적 파일을 로컬 경로로 읽는다. 이 비용은 usage에 포함되지만 HTTP 요청 지연이나 시각적 UI 사용성의 실험은 아니다. B/C의 지도 도메인 제한은 지시와 사후 로그 감사이며 강제 네트워크 차단이라고 주장하지 않는다. 20회 외부 예산은 모델에 지시했지만 사후 CLI 로그만으로 정확한 원자 횟수를 확인하지 못했다. 하한이 20 이하라는 사실만으로 준수를 인정하지 않는다. 15분은 실행기 timeout으로 제한한다.

수집한 usage는 CLI 보고 범위의 모델 입력/출력/캐시 토큰이다. 입력과 캐시 입력을 별도로 보고하며 입력 토큰 전체를 유료 청구량으로 해석하지 않는다. 최초 유효 후보 시간은 현재 계측하지 않아 null이다. `summarize_r0_pilot.py`는 실행 지표를 집계할 뿐 공식 근거의 정확성을 자동 채점하지 않는다.

시각적 G1은 브라우저 기능 제한으로 미관측이며 코드/데이터 경로만 사전 검사했다. 본 실행은 UI 통과나 통계적 효용 입증으로 표시하지 않는다. R1 일반화 holdout은 이 v1에 포함하지 않아 그 독립성을 주장할 수 없다. R0 결과 확인 후 동일 과제를 R1의 독립 일반화 점수로 재사용하지 않는다.

실행 결과를 고정한 뒤 원문 근거·조건 오염·예산 초과·잘못된 보류·결합 주장 여부를 별도로 채점하고 외부 AI 검토를 요청한다. 새 발견은 R0 종료 전에 카탈로그에 넣지 않는다.
