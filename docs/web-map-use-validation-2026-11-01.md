# 웹 AI의 인터넷 지도 사용 검증

2026년 11월 1일 BW Edge 확장을 통해 ChatGPT·Gemini·Claude·Perplexity·DeepSeek·Grok에 같은 세 과제를 전달하고 새 응답을 확인했다. **외부 검색 API 키 없이도 지도 사용과 조건·종료 판단을 검증할 수 있었다.** 일부 제공자는 직접 정적 파일을 읽었고, 접근이 막힌 제공자는 책임자가 전달한 지도 노드로 검증을 이어갔다. 접근 실패를 지도 데이터 부재로 취급하지 않았다.

현재 지도에서 본문 추출 후보를 찾을 수 있었고, 장소명 지오코딩과 공식 대여소 ID 대응을 구분할 수 있었다. 동시에 존재하지 않는 노드 인용, 실제 작업 완료와 답변 완료의 혼동, 재현되지 않는 결함 지적이 나왔다. 따라서 웹 AI의 열람·성공·리뷰 자기보고는 정본과 실제 관측으로 대조해야 한다.

## 과제와 검증 범위

| 과제 | 요구 | 기대 판정 |
|---|---|---|
| A | 공개 URL 본문을 Markdown으로 읽는 후보를 Operation→Binding→Evidence로 조회하고 입력·출력·인증을 확인 | 문서 기반 후보 발견. 실제 API 호출은 요구하지 않음 |
| B | 서울 장소명 좌표 후보 조회, 무인증과 상업적 무료 이용이 모두 필수 | 필터 일치와 전체 조건 충족을 구분. 근거가 없으면 보류하고, 공식 조건이 위반이면 부적합 |
| C | 서울 OD ST-* ID→공식 좌표→EPSG:5179 250m 격자 연결의 ID·시점·원좌표계 근거 조회 | 지도 내 근거가 없으면 범위를 한정해 종료. 접미사·장소명 매칭과 인터넷 전체 부재 단정 금지 |

정본은 `catalog_revision=dedb559d257be35d`, 7서비스·16동작·9연결·108 Evidence metadata·정보원 0건이다. 108건은 독립 출처 108개나 독립 검증 108회를 뜻하지 않는다. 책임자가 공개 manifest·인덱스·선택 상세를 실제 HTTPS로 읽어 확인했다.

모든 제공자가 같은 기존 대화에서 출발했으며 이전 맥락·모델·열람 도구·접근 경로가 달랐다. 일부는 피드백·중계 후 재판정했다. 이는 사용 경로와 실패 유형을 찾는 **형성 평가**이며, 조건을 통제한 18회 비교나 미사용 holdout 평가가 아니다. 웹 AI의 실토큰·최초 적합 후보 시간·원자 열람 수를 계측하지 않아 효율 우위나 성공률을 산출하지 않았다.

## 제공자별 사용 결과

| 제공자 | 초기 접근과 관측 | 후속 검증 |
|---|---|---|
| ChatGPT | 직접 Pages 접근은 DisabledError. GitHub connector로 배포 artifact를 받아 지도 노드를 읽었다고 보고 | 실제 후보·Binding·Evidence ID는 정본과 일치. 답변 완료를 실제 작업 완료로 표시한 것을 인정하고 API·조인 모두 not_run으로 정정 |
| Gemini | direct를 보고했으나 존재하지 않는 ID·상세 경로를 인용하고 Context7을 임의 URL Markdown 추출 후보로 선택 | 인용한 6개 경로가 실제 404임을 확인해 초기 판정 불인정. 정정 요청이 입력창에 남고 삭제 확인도 실패해 새 정정 응답은 미확인 |
| Claude | manifest는 직접 읽었으나 구성한 browse URL은 PERMISSIONS_ERROR. 시작 HTML은 JS 셸로 읽힘 | 요청한 인덱스·Operation·Binding·Evidence를 단계 중계. 정확한 ID를 요청하고 상업 이용 근거가 없을 때 unknown으로 보류 |
| Perplexity | Pages 두 주소에서 Failed to fetch content. 없는 ID를 만들어 답하지 않음 | 중계 후 본문 추출·지오코딩 후보를 선택. 상업 이용은 metadata만으로 확정하지 않음. Tavily 인증 원문은 직접 재확인했다고 보고 |
| DeepSeek | 첫 페이지 설명은 읽었으나 ID·상세·Evidence 미열람을 명시 | 중계로 실제 후보 ID·Binding·Evidence를 확인. 범용 지오코딩으로 ST ID 대응을 대체하지 않음 |
| Grok | 직접 manifest·인덱스·상세·연결된 원문을 읽었다고 보고. A 후보와 B 상업 무료 부적합, C 범위 내 보류를 구분 | 실제 JSON을 제시하자 Tavily 인증 불일치 지적을 철회하고, 조건 위반/근거 충돌·실제 작업 상태도 정정 |

직접 접근은 제공자의 보고와 인용 내용을 대조한 것이다. 각 제공자의 네트워크 내부 로그를 독립 확보했다는 뜻은 아니다. 중계는 책임자가 취득한 노드와 전송 내용을 기록했으며 제공자가 직접 Pages를 열었다고 세지 않는다. 직접 접근·artifact 접근·중계 접근을 합쳐 하나의 접근 성능으로 비교하지 않는다.

ChatGPT가 보고한 artifact ID `13083199315`는 GitHub API에서 `github-pages`, workflow run `41307429463`, 만료되지 않은 artifact로 확인됐다. 보고한 manifest의 generated_at `2026-11-01T21:38:04+09:00`과 catalog revision도 배포본과 일치했다. 이 확인은 artifact와 내용의 존재를 보강하지만 ChatGPT의 실제 다운로드 도구 호출 전체를 독립 증명하지 않는다. connector의 사용자·인증 방식은 미관측이다.

## 정본 대조와 반례

### 실제 후보와 수행 상태

A의 실제 후보는 `op_tavily_extract_url`→`bnd_tavily_web_http`이다. Operation은 `urls`, 선택 `format`, `extracted_content`, `effect=read`를 선언하고 Binding은 `POST /extract`, `auth_schemes=["bearer"]`를 제공한다. Context7의 라이브러리 문서 검색은 이 입력·기능과 다르다.

B의 후보는 `op_search_geocoding`→`bnd_open_meteo_geocoding_http`이다. 무인증 표시만으로 상업적 무료까지 충족했다고 판단할 수 없다. 책임자가 [지오코딩 문서](https://open-meteo.com/en/docs/geocoding-api), [요금 안내](https://open-meteo.com/en/pricing), [서비스 조건](https://open-meteo.com/en/terms)을 직접 조회했다. 공용 무료 서비스의 비상업용 조건과 구독의 상업 이용 라이선스가 확인돼, 이번 B의 원격 서비스 요구에는 부적합하다. 데이터 라이선스의 허용 범위와 서비스 무료 사용 조건은 구분한다.

metadata만 받은 단계의 unknown은 적절했다. 추가 공식 원문 확인 뒤에는 같은 조건을 violated로 갱신할 수 있다. 필수조건 위반과 같은 주장에 대한 Evidence 충돌도 구분해야 한다. 책임자의 원문 조회는 새 계측 도구로 3개 동작과 응답 해시를 기록했고 짧은 발췌·출처를 중계했다. 이는 외부 검색 API 호출이 아니다.

C에서는 인덱스 전체 항목의 목록·목적과 요청된 문자열 점검을 대조했다. ST-, 따릉이, 대여소, EPSG:5179, 250m의 포함 항목은 각각 0건이었다. 문자열 0건만으로 의미상 모든 가능성을 증명하지 않으며, 판정은 현재 지도 인덱스의 수록 범위에 한정한다. 실제 API 호출·서울 OD 조인·좌표변환은 이번 웹 AI 과제에서 수행하지 않았다.

### 존재하지 않는 노드 인용

Gemini가 읽었다고 제시한 다음 경로는 모두 책임자의 실제 조회에서 HTTP 404였다. 기준 경로는 `https://ik-e.github.io/agent-capability-map/catalog/v1/`이다.

- `detail/service_context7.json`
- `detail/binding_context7_remote_mcp_default.json`
- `detail/service_open_meteo.json`
- `detail/binding_open_meteo_geocoding.json`
- `index/search_index.json`
- `index/categories.json`

실제 인덱스 경로는 `search/index.json`, 분류는 `browse/index.json`, 상세는 `operations/`, `bindings/`, `evidence/` 아래다. 존재하지 않는 경로와 ID를 인용한 초기 답변을 지도 열람·문서 검증 성공으로 인정하지 않는다. 추가 원문을 받은 후의 정정은 초기 시행의 독립 성공으로 소급하지 않는다.

### 재현되지 않는 결함 지적

Grok은 Tavily의 검색 인덱스에 `none`과 `bearer`가 함께 있고 Binding 상세는 `bearer`만 있다고 지적했다. 실제 배포 인덱스의 `op_tavily_extract_url.binding_summaries`와 Binding 상세는 모두 `bearer`만 있었다. 따라서 이 지적을 확인된 생성 버그나 수정 근거로 채택하지 않았다. 다른 후보의 속성을 섞었을 가능성은 추정이며 원인으로 확정하지 않는다.

Grok은 정정 응답에서 해당 지적을 철회했다. Claude·Perplexity·DeepSeek은 metadata만 받은 단계에서는 B를 unknown으로 두고, 책임자가 공식 서비스 조건의 짧은 발췌를 중계한 뒤 위반으로 갱신했다. 일부 응답이 발췌에 없는 라이선스·가격표 내용까지 덧붙인 부분은 이번 중계로 새로 확인한 사실로 세지 않는다.

## 확인한 개선 우선순위

1. **존재·관계·수행 상태를 검증한다.** 후보 ID, Binding 연결, Evidence 참조와 실제 HTTP 결과를 검사하고 모르는 노드를 완료 근거로 쓰지 못하게 한다. 질문에 답한 완료와 외부 작업 수행 완료는 별도 필드로 유지한다. 자유 서술의 상태를 그대로 자동 완료 판정에 사용하지 않는다.
2. **기계용 진입 경로를 명시한다.** manifest의 절대 URL entrypoint와 JS 실행 없이 따라갈 수 있는 정적 링크·안내를 검토한다. 상대경로 해석이 막힌 Claude 사례를 회귀 사례로 사용한다. 일부 웹 도구의 접근 실패를 사이트 전체 장애·CORS 오류로 단정하지 않는다. 책임자의 동일 공개 JSON 조회는 HTTP 200이었다.
3. **선택에 반복해서 필요한 근거를 보강한다.** 상업 서비스 이용조건과 가격·데이터 라이선스 범위를 구분하고, 중요 미확인을 명시한다. A/B의 정규화된 outputs에는 전용 Evidence가 없었다. 현재 최소 계약이 outputs Evidence를 필수로 강제하지 않으므로 즉시 스키마 위반으로 단정하지 않되, 선택 판단의 빈틈으로 기록한다. 한 필드의 반복 요구를 먼저 해결하고 모든 제약 필드를 한꺼번에 늘리지 않는다.
4. **근거의 독립성과 한계를 표시한다.** 같은 URL·일반적인 locator를 공유하는 Evidence 여러 건을 독립 출처 여러 개로 세지 않는다. 실제 출처의 구체 구간·확인 시점의 정밀도·스냅샷을 보강하고, 지도에 저장된 verified와 이번 원문 재확인을 구분한다.

Operation 요약에 인증을 단순 합집합으로 복제하자는 제안은 바로 채택하지 않는다. 같은 Binding의 조건을 함께 평가하는 기존 계약을 유지하고, 이미 존재하는 Binding 요약을 필요한 만큼 노출하는 방식을 먼저 검토한다. 중계에서 생략한 필드가 있다는 이유만으로 원래 인덱스에 그 필드가 없다고 판단하지 않는다.

## 브라우저 작업 관측

BW 연결은 기존 Edge 확장을 재사용했고 다른 프로젝트의 탭을 닫거나 새 검증 탭을 만들지 않았다. 최신 요청 표시와 이전 답변이 어긋나는 화면, Gemini의 미전송 초안, Grok의 대기열이 관측됐다. 전송 결과 불명 상태에서는 중복 전송하지 않고 본문·입력창·현재 요청 표시를 대조했다. 검증용 세션만 같은 URL로 새로고침해 저장 상태를 확인했고 새 요청이 저장되지 않은 경우에만 재전송했다. 생성 완료 여부·전송 여부·새 답변 내용은 별개의 관측이다.

Gemini의 긴 정정 초안은 전송 완료가 확인되지 않았고, 이 작업이 만든 초안임을 확인한 후 삭제를 시도했으나 “현재 6565자가 남아 있다”는 검증 오류가 반환됐다. 전송이나 삭제를 성공으로 기록하지 않았다. 초안 원문과 오류는 비공개 실행 기록에 보존했으며, 초기 오답을 정정 완료로 표시하지 않는다. 이 브라우저 입력 문제와 지도 데이터 오류를 같은 문제로 합치지 않는다.

이번 기록은 검색 API 미설정과 지도 사용 가능성을 구분한다. 지도 접근과 중계 기반 판단 검증은 가능했으며, 원자 요청·토큰을 통제하는 별도 효율 비교의 검색 gate는 여전히 미통과다. 두 검증을 같은 합격·실패로 합치지 않는다.

원문 대화·요청·중계 데이터·HTTP 점검은 Git 제외 경로 `evals/runs/web-map-use-2026-11-01/`에 보존한다. 공개 문서에는 사용자 대화 주소나 원문 대화를 포함하지 않는다.
