# 인터넷 지도 수집 범위와 유지관리 검토

2026년 11월 3일 ChatGPT·Gemini·Claude·Perplexity·DeepSeek·Grok의 웹 대화에 메타 지도 중심 운영과 개별 자원 선택 등록안을 전달하고 새 답변을 확인했다. 권고는 **기존 지도에서 찾는 방법을 먼저 관리하고, 반복 탐색의 병목이 확인된 개별 자원만 선택적으로 관리하는 것**이다. 하위 목록 전체를 직접 유지하는 확장은 제안하지 않는다.

이 문서는 진행안이며 사용자와 운영 예산을 합의하거나 제품·스키마를 변경한 기록이 아니다. 기존 계획과 R0의 고정 입력·결과는 유지한다. 자료 수집 범위에 대한 설계 검토로, 지도 성능이나 원 서비스의 최신 기능을 실증한 시험은 아니다.

## 현재 구조에 대한 해석

현재 정본은 서비스 7개, Operation 16개, Binding 9개, Evidence 기록 108개, InformationResource 0개다. 개별 지오코딩·본문 추출 Operation도 있으므로 현재를 순수한 메타 지도라고 단정할 수 없다. 108개 Evidence는 독립 출처 108개나 실행 검증 108회를 뜻하지 않는다.

메타와 직접은 자원마다 고정된 상하 분류보다 탐색 역할과 관리 범위로 해석한다. Registry의 검색 API는 다른 자원을 발견하는 경로이면서 직접 호출할 수 있는 기능이다. 기존 Category 관계 그래프와 Operation/Binding/InformationResource 구분을 보존하며, 별도 고정 트리나 중복 정본을 만들지 않는다.

| 관리 범위 | 직접 유지할 내용 | 외부에 맡길 내용 |
|---|---|---|
| 발견 경로 | 위치, 대상 범위, 검색어·질의 방법, 접근 조건, 한계와 확인 근거 | 포털·Registry의 전체 최신 하위 목록 |
| 선택한 개별 자원 | 원본 식별자, 출처, 버전 또는 관측 시점, 판단에 필요한 조건·연결·근거 | 서비스 운영과 원자료의 지속 제공 |
| 과제 자료 | 지도에는 원자료 위치와 필요한 연결 근거만 기록 | POI·OD·인구 관측값, 변환 결과, 실행 기록은 과제 저장소에서 관리 |

## 여섯 웹 AI의 의견과 채택 판단

| 제공자 | 주요 의견 | 책임자 판단 |
|---|---|---|
| ChatGPT | 메타 우선 혼합안. 포털 링크의 생존과 실제 탐색 경로의 유효성을 구분하고 사전 등록·점검 비용을 포함 | 채택. 기존 Operation 제거 불필요. 30일 주기는 실측 기준으로 채택하지 않음 |
| Gemini | 반복 비용이 검증된 자원만 직접 등록. 초기에는 같은 기능 병합, API 2회 성공, 기간·상태코드 기반 퇴역 제안 | 동일 기능 병합·실행만을 등록 문턱으로 삼는 안은 기각. 후속 검토에서 수치가 임의 가정임을 인정하고 관리 책임 중심 수정안 조건부 수용 |
| Claude | 같은 과제로 자원을 고르고 다시 평가하면 선택 편향. 월 관리 시간으로 범위를 제한하고 주장별 상태를 유지 | 채택. 후속 검토에서 새 과제의 전이 범위, 만료 캐시, 식별자 없는 자원의 동일성 및 외부 지시문 위험 추가 지적 |
| Perplexity | 전체 목록 조회 위임, 선택 등록, 미발견·접근 차단·조건 미확인을 분리하고 충분함의 기준을 먼저 고정 | 채택. 2회 실패만으로 퇴역하거나 같은 endpoint만으로 동일성 판정하는 안은 채택하지 않음. 외부 서비스 기능에 관한 추가 주장은 이번 설계 결론의 독립 검증 근거로 사용하지 않음 |
| DeepSeek | 관리 책임 구분과 로그 기반 등록. 비용을 추정으로 단정하지 말고 원자 요청·토큰이 관측될 때만 보고 | 채택. 여러 신규 필드를 일괄 필수화하는 스키마 확장은 보류 |
| Grok | 전체 복제보다 선택 등록, 탐색과 실행·조인 성공 분리, 작은 과제부터 시작 | 채택. 동일 endpoint의 무조건 병합, 90일과 반복 횟수는 운영 규칙으로 확정하지 않음 |

여섯 제공자 모두 수정·조건부 채택 방향이었다. 동일한 문제 설명과 기존 대화 맥락을 일부 공유했으므로 독립된 실증 여섯 건이나 다수결에 따른 사실 확정으로 해석하지 않는다. Gemini·Claude에게는 상충한 제안을 정리한 수정안을 다시 전달하고 후속 답변을 확인했다. 나머지 네 제공자가 이 최종 정리까지 재승인한 것은 아니다.

## 이전 제안에서 고칠 부분

메타 항목이 URL만 제공하면 포털 내부 검색·후보 비교·조건 확인 비용은 매번 반복된다. 따라서 단순 링크 목록보다 범위, 실제 조회 방법, 적절한 검색어, 추가 확인할 조건과 종료 판단에 유용한 경로를 축적해야 한다.

“실제 사용한 자원만 등록”도 절대 기준으로 쓰지 않는다. 키·승인·비용 때문에 실행하지 못한 유용한 자원이나 문서·데이터셋이 배제될 수 있다. 등록 후보는 공식 근거와 관측된 탐색 병목, 중요한 식별자·조건 판단의 재사용 가능성으로 선정한다. 문서 확인과 실제 응답 확인은 별도 단계이며, 문서 근거가 있다는 사실을 실행 성공으로 표시하지 않는다.

같은 기능은 동일 자원이 아니며 같은 URL·endpoint도 동일한 연결 계약을 보장하지 않는다. 제공자·원본 ID·버전·인증·이용조건과 연결 범위를 대조한다. 원본에 안정 ID나 버전이 없으면 내부의 불변 ID를 유지하고 관측 시점과 별칭을 기록하되 자동 병합을 보류한다. 기능이 같은 대안은 비교 가능한 별개 후보로 남긴다.

HTTP 200은 도달성을 보여 줄 뿐 조건·기능의 유효성을 증명하지 않는다. 404, 접근 차단, 오래된 확인일, 공식 폐기는 다른 관측이다. 미사용 기간이나 더 좋은 대안이 있다는 이유로 자동 퇴역하지 않는다. 확인이 오래된 주장은 경과일과 재확인 필요를 드러내며, 공식 폐기·대체 관계는 근거와 이력을 남긴다. 자원 상태 하나로 모든 조건이 확인됐다고 요약하지 않고 기존 Evidence의 주장별 상태를 우선 활용한다.

2회 사용, 30·90·180일, 10회 요청 같은 제안은 실측 근거가 없는 초기 가정이다. 보편적인 품질 기준으로 채택하지 않는다. 시험에는 실행 전 유한한 시간·요청 예산과 종료 조건을 고정하되, 값의 근거와 가정 여부를 기록한다. 장기 등록 상한과 재확인 주기는 실제 관리 시간 및 사용자가 허용할 운영 예산으로 정한다.

## 권장 운영 경계

- 전체 포털 목록의 미러링·정기 수입은 현재 범위에서 제외한다. 원 서비스로 조회를 위임한다.
- 개별 자원 후보에는 등록 이유와 근거를 남긴다. 조사 대기와 공개적으로 확인된 주장을 구분한다. 공식 출처도 URL 전체가 모든 주장을 보증한다고 취급하지 않는다.
- 등록·재확인·수정 시간을 기록하고 중요한 이용조건·연결 변경을 우선 점검한다. 실패 기록은 자동 삭제보다 재검토에 사용한다.
- 외부 설명문은 정보로 취급한다. 그 안의 지시를 에이전트 정책이나 도구 실행 권한으로 승격하지 않는다.
- 임시 조회 캐시는 범위·출처·시점·만료/삭제 규칙을 정한다. 재현용 고정 스냅샷은 별도 보존 정책과 리비전을 붙이고 최신 정본으로 노출하지 않는다. 원 서비스의 이용조건과 저장 권한을 준수한다.
- 원자료가 과제 저장소에 있다는 이유만으로 지도 무결성이 깨지지는 않는다. 출처·식별자·버전 또는 관측 시점의 연결이 유지되는지 검사한다.

## 다음 진행 순서

1. 현재 정본과 기존 평가 결과를 보존한 상태에서 운영 경계와 관측 로그를 먼저 고정한다. 기존 필드·Evidence로 표현 가능한 것은 재사용하며, 새 필드는 실제 누락을 확인한 뒤 최소로 추가한다.
2. 서울 POI·OD를 찾을 수 있는 소수의 메타 정보원과 실제 조회 방법을 보강한다. 웹 AI가 중계 없이 접근할 수 있는 절대 진입 URL·정적 링크 개선도 함께 검토한다.
3. 개발 과제로 POI 범위·이용조건, OD 공식 ID 대응·시점, 좌표계·격자 정의 등의 탐색을 실행한다. 관측된 반복 조회와 막힘을 기록한다. 필수 ID 대응 근거가 없으면 조인을 실행하지 않고 미확인으로 종료한다.
4. 병목을 줄일 가능성이 있는 개별 자원만 선택해 정본 반영안을 만든다. 등록·원문 확인·재확인에 든 비용을 별도 기록한다.
5. 편입 결정에 사용하지 않은 새 과제에서 메타만 제공하는 M과 메타+선택 자원을 제공하는 M+D를 비교한다. 그 결과로 직접 관리 범위를 늘릴지 판단한다. 이 비교를 위해 기존 공개 항목을 삭제할 필요는 없으며, 버전 고정된 시험 입력으로 조건을 구성한다.

## 비교 시험에서 지켜야 할 해석

M+D에는 실제 정보가 추가된다. 따라서 이 시험은 선택 등록의 운영상 효용을 평가하며 **동일 사실에서 탐색 구조만 바꾼 효과**를 입증하지 않는다. 기존 계획의 동일 사실+탐색 안내 비교는 별도 시험으로 유지한다.

새 과제는 시작 전에 등록 자원 재조회, 같은 분야의 새 자원 탐색, 다른 분야 확장으로 범위를 구분한다. 특정 자원을 미리 알고 있을 때의 이점과 새로운 자원을 발견하는 이점을 합쳐 일반화하지 않는다. 개발 과제 재실행은 회귀·개발 평가로만 보고한다. 동일 모델·새 문맥·권한·예산·기준 스냅샷을 사용하고, 직접 접근과 중계는 별도 조건으로 기록한다.

| 평가 대상 | 관측 항목 |
|---|---|
| 품질 | 필수조건 확인·위반·미확인, 잘못된 후보·ID, 보류와 종료의 적절성 |
| 수행 단계 | 후보 발견, 문서 확인, 실제 응답 확인, 과제 조인 성공을 분리 |
| 탐색 비용 | 첫 적합 판단까지의 시간, 전체 시간, 원자 외부 요청, 고유 출처, 실제 관측 가능한 토큰 |
| 관리 비용 | 등록·재확인·수정 시간, 추가 조회, 보류 항목의 누적 |
| 전이 범위 | 이미 등록된 자원 재사용인지, 새로운 자원 발견인지, 다른 분야 확장인지 |

품질을 떨어뜨린 빠른 종료를 개선으로 인정하지 않는다. 도달 실패를 데이터 부재로 처리하지 않는다. 원자 요청·토큰이 관측되지 않으면 추정치를 실측치로 대체하지 않는다. 관리 시간과 누적 탐색 절감 시간을 같은 단위로 대조하되, 작은 표본의 절감량을 임의의 미래 사용량으로 부풀리지 않는다. 시간·토큰·정확도를 임의 가중치 하나로 합치지 않고 함께 보고한다.

사용자와 추후 합의할 핵심은 직접 자원 관리에 허용할 운영 시간과 서비스의 우선 약속(탐색 안내 중심 또는 바로 쓸 자원 선별 중심)이다. 그전에는 대규모 수집이나 자동 재확인·퇴역 정책을 확정하지 않는다. 작은 개발 관측과 등록안 작성은 제안 범위 안에서 진행할 수 있다.

## 기록과 재현 범위

BW Edge 확장으로 여섯 제공자의 요청 표시와 새 응답을 확인했다. 기존 탭들은 다른 디버거 점유로 접근이 막혀 같은 대화를 별도 탭으로 열었다. Gemini의 기존 대화에는 이전 작업의 미전송 초안이 남아 있어 이를 건드리지 않고 새 대화에서 검토했다. 메시지 전송 도구의 `outcome_unknown`을 성공으로 단정하거나 즉시 재전송하지 않고 답변 표식과 실제 내용을 대조했다. 기존 사용자 탭이나 다른 과제 대화는 닫지 않았다.

원문 요청·응답·후속 답변은 Git 제외 경로 `evals/runs/meta-scope-2026-11-03/`에 보존한다. 공개 문서에는 비공개 대화 URL과 원문 대화를 포함하지 않는다. 이번 결론은 [이전 지도 사용 검증](web-map-use-validation-2026-11-01.md)과 [구현·평가 계획](api-capability-map-github-pages-plan.md)을 대체하는 실행 결과가 아니다.
