# 메타 지도 보강과 포털 탐색 개발 결과

2026년 11월 3일 메타 지도 우선 계획에 따라 관측 계약을 고정하고 공식 정보원 두 곳과 선택 자원 한 건을 추가했다. 포털 한정 모델 비교 네 번을 실행했으나 **추가한 개별 자원이 실제로 읽히지 않아 선택 등록의 효율 효과를 입증하지 못했다.** 검색어와 공식 자료명 사이의 누락을 고치고 별도 회귀를 진행했다. 대규모 수집과 원자료 복제는 시작하지 않았다.

## 지도에 반영한 내용

| 항목 | 반영 범위 |
|---|---|
| 공공데이터포털 | 공개 목록 탐색, 홈페이지가 선언한 검색 URL 형식, 키워드·기관 검색, API 키/승인과 개별 이용허락의 별도 확인 안내 |
| 서울 열린데이터광장 | POI·공공자전거·인구·격자 탐색 경로, 실제 검색 폼과 개발 조회에서 작동한 GET 경로, 상세 식별 방법과 한계 |
| 따릉이 대여소 마스터 OA-21235 | OD 상세 OA-21229가 ID 정보의 참고 대상으로 직접 연결하는 공식 자료의 위치·설명·개별 이용허락. 실제 ST 값·좌표계·과거시점 대응은 미확인으로 표시 |

기존 7서비스·16Operation·9Binding을 유지하고 InformationResource 3개와 주장별 Evidence 15개를 추가했다. Evidence 총 123개는 독립 출처 123개를 뜻하지 않는다. 포털 두 곳 전체에 동일한 이용허락이 있다고 표시하지 않고 `license_status=unknown`을 유지했다. 마스터의 개별 상세는 공공누리 1유형을 표시한다.

새 스키마 필드를 만들지 않고 기존 `scope`, `update_notes`, `reference_date`와 Evidence를 사용했다. 사람용 상세에 탐색 방법·한계·확인 시각을 표시하며, 동일 정본에서 JavaScript 없는 정적 분류 목록·정보원 상세를 생성한다. manifest에는 절대 URL `entrypoints`를 추가했다. 기존 상대 URL 계약은 유지한다.

## 사전 계약과 개발 관측

[포털 경로 점검 계약](../evals/meta-first-v1/protocol.json)을 첫 원문 조회 전에 잠갔다. 시작점은 공공데이터포털과 서울 열린데이터광장이며 공식 호스트만 허용했다. 30개 원자 동작·600초는 초기 개발 예산이다. 실제로 26개 동작·26개 네트워크 시도를 실행했고 모두 HTTP 열람에 성공했다. 동작 실행 시간 합은 8.735초, 첫 시작부터 중단까지의 경과시간은 223.720352초였다. 후자는 책임자의 판독·후속 요청 간 시간을 포함한다. API 실응답·조인은 수행하지 않았다.

관측된 병목과 후속 판단:

- 공공데이터포털의 메뉴 일부는 JavaScript 경유였지만 홈페이지 SearchAction이 검색 URL 형식을 제공했다. 이를 실제 조회로 확인해 탐색 안내에 반영했다.
- 서울 검색 결과의 실제 상세 경로는 `goView` 요소의 `data-rel`에 있었다. 일반 href 목록에 섞인 추천 자료 두 건을 먼저 열었으나 과제와 무관함을 확인해 제외했다. 실제 상세 속성을 확인한 뒤 올바른 대여이력·대여소 자료로 이동했다. 이 추가 조회도 26개 동작에 포함했다.
- 전국 상가정보 후보에서 위치·업종 설명, 파일명 기준일과 개별 이용허락은 확인했으나 모든 건물·거주·교육 장소의 완전한 POI 목록으로 해석하지 않았다.
- 서울 체류인구 안내에서 250m 격자와 5179 SHP 안내를 찾았다. 격자 파일·정의서·실제 공간 결합은 검사하지 않았다.
- 대여소 일반 현황과 OD용 마스터를 구분해야 했다. [OD 상세](https://data.seoul.go.kr/dataList/OA-21229/F/1/datasetView.do)의 명시적 참조로 [마스터 상세](https://data.seoul.go.kr/dataList/OA-21235/S/1/datasetView.do)에 도달했기에 이 자원 한 건만 선택 등록했다. 이름이나 ID 접미사를 임의 대응하지 않았다.

관리 로그의 항목과 source 이벤트는 고정했으나 자료 작성·재확인·수정에 든 전체 시간을 완전하게 분리 계측하지는 못했다. 따라서 운영 비용이 탐색 절감을 상쇄하는지나 장기 손익분기점은 계산하지 않는다. 이후 등록부터 작업 시작·종료 시각을 활동별로 수집해야 한다.

## 포털 한정 네 시행

[별도 비교 계약](../evals/meta-first-v1/comparison.json)을 고정한 뒤 실제 stdio MCP에서 서울 검색 페이지 open/find를 보정했다. 일반 웹 query는 사용하지 않았다. 검색 연결의 기존 503·키 미설정을 해결했거나 일반 웹 비교 gate를 통과했다는 뜻은 아니다. 이번 검증은 공식 포털 URL 조회와 그 안의 탐색만 대상으로 한다.

조건은 M(메타 정보원 두 건)과 M+D(같은 입력에 선택 마스터 추가)이며 기존 Operation은 공통으로 제공했다. 정적 산출물의 동결 사본을 시험용 catalog MCP로 읽었다. 이는 직접 Pages 접근이 아니다. 모델은 gpt-6.1-sol, medium, 새 CLI 문맥, 읽기 전용, 동작 10개·180초였다. 등록 자원 재조회와 선택 등록에 사용하지 않은 버스정류소 탐색을 나눠 조건 순서를 교차 배치했다. 각 조합은 한 번뿐이다.

| 과제 | 조건 | 경과 초 | 실행 원자 동작 | 네트워크 시도 | 비캐시 입력 토큰 | 출력 토큰 |
|---|---|---:|---:|---:|---:|---:|
| 등록 마스터 재조회 | M | 79.547 | 8 | 8 | 62,922 | 1,685 |
| 등록 마스터 재조회 | M+D | 70.563 | 9 | 7 | 53,810 | 1,808 |
| 새 버스정류소 탐색 | M | 72.437 | 5 | 4 | 42,245 | 1,674 |
| 새 버스정류소 탐색 | M+D | 55.343 | 5 | 4 | 54,656 | 1,805 |

비캐시 입력은 CLI의 input_tokens에서 cached_input_tokens를 뺀 값이다. 캐시 사용량·원래 집계는 [공개 집계](../evals/meta-first-v1/comparison-summary-2026-11-03.json)에 보존했다. 토큰은 모델 사용량이며 외부 서비스 전체 비용은 아니다. 실행 시간은 CLI 초기화·모델 판단·도구 응답·최종 출력을 포함한다. 첫 적합 후보 시간은 계측하지 않았다.

각 시행에 잘못된 연구 도구 인자 요청 한 건이 있었으며 실제 실행된 원자 동작과 분리했다. M+D 마스터 응답은 이를 합쳐 “외부 동작 10회”라고 설명했지만 실제 실행 로그는 9개였다. 이 자기보고를 실측 카운터로 채택하지 않았다. `find`는 로컬 문서 조회이므로 원자 동작 수와 네트워크 수가 다를 수 있다.

### 답변과 원문 대조

네 답변의 총 20개 주장에 연결된 이벤트 ID·성공 상태·URL·응답 SHA256을 대조했고 참조 무결성 오류는 없었다. 별도 원문 판독에서는 다음을 확인했다. 자동 참조 검사 자체가 의미적 정확성을 보증하는 것은 아니다.

- 두 마스터 시행 모두 OA-21229→OA-21235 관계와 공식 ID·주소·좌표 제공 설명, 데이터 갱신일 2026-11-03, 메타정보 수정일 2026-02-27, 공공누리 1유형 표시를 확인했다. ST 값·좌표계·과거 대응은 미확인으로 남겼다.
- 두 버스 시행 모두 [서울 버스정류소 위치정보](https://data.seoul.go.kr/dataList/OA-15067/S/1/datasetView.do)를 찾았다. 정류소ID·ARS-ID 설명, 메타정보 수정일 2025-11-17과 데이터 갱신일 2026-09-02 및 개별 이용허락을 구분했다.
- 버스 원문은 좌표계를 `WGS84 (EPSG-5179)`로 함께 표기했다. 모델들은 이를 실제 좌표계가 확정됐다는 근거로 채택하지 않았다. 명세서·실제 열·공식 좌표계 정의를 추가 확인할 대상으로 남긴다.
- 문서 말미의 서비스 종료/URL 오류 안내 문구만으로 현재 서비스가 종료됐다고 단정하지 않았다. 문서 접근과 실제 서비스 운영은 분리했다.
- 어느 시행도 API 호출·파일 다운로드·실제 좌표 수신·전체 수록률·조인 성공을 주장하지 않았다.

### 선택 등록 효과를 판정할 수 없는 이유

두 M+D 시행 모두 선택한 마스터 상세를 읽지 않았다. 마스터 재조회 시행의 검색어 `공공자전거`가 축약된 자료명과 별칭에 없어서 메타 정보원만 반환됐다. M과 M+D 마스터 시행은 결국 같은 서울 메타 정보원 상세를 읽었다. 버스 시행도 두 메타 정보원만 사용했다.

따라서 표의 시간·토큰 차이를 선택 자원 추가의 인과 효과로 해석하지 않는다. 버스 M+D는 시간은 짧고 비캐시 입력은 더 많았다는 관측까지만 가능하다. 등록 재조회는 독립 발견 holdout도 아니다. 추가 데이터가 실제 노출·열람됐는지 먼저 점검해야 한다는 개발 실패 사례로 보존한다.

공식 자료명의 `공공자전거`를 복원하고 해당 검색어로 마스터가 반환되는 회귀 검사를 추가했다. 수정 전 정본 `cc9a9ed324ac60c6`의 네 시행은 유지하며 수정 후 정본 `2c6a80dee032e16b`와 결과를 합산하지 않는다. 별도 [자료명 수정 회귀 계약](../evals/meta-first-v1/name-regression.json)은 개발 과제 한 건의 경로 재현만 확인하며 새로운 효율 비교로 세지 않는다.

수정 후 새 문맥 회귀에서 `공공자전거` 검색이 마스터를 반환했고 모델이 `res_seoul_bike_station_master` 상세를 실제 읽었다. 이후 공식 원문 두 곳을 열어 관계와 조건을 확인했다. 경과시간 38.516초, 원자 동작 3개·네트워크 시도 2개, 비캐시 입력 32,343·출력 1,180토큰이었다. [회귀 집계](../evals/meta-first-v1/name-regression-summary-2026-11-03.json)에 별도 기록한다. 같은 개발 과제를 수정 후 반복했으며 동시 대조군도 없으므로 이전 네 시행과 비교한 새 효율 입증으로 사용하지 않는다.

## 다음 관리 결정

현재 관리 범위는 메타 정보원 두 건과 마스터 한 건으로 유지한다. 이번 관측만으로 직접 자원 수를 늘리지 않는다. 다음 확인은 공식 검색어·분류 탐색에서 선택 자원이 실제 반환·열람되는지, 이후 새 입력에서 원문 검증 요청이 줄어드는지다. 다음 비용 비교에서는 활동별 관리 시간을 시작부터 기록한다. 서울 실제 결합은 ST 값·시점·좌표계 근거를 확보한 뒤 별도 표본으로 검증한다.

원문 이벤트·응답·동결 입력·CLI 대화는 `evals/runs/`에 비공개로 보존한다. 과거 R0의 입력·결과와 동일 사실+안내 비교를 이번 결과로 대체하지 않는다.

## 제품 검사 범위

카탈로그 계약 검사 4개, 기존 판정·계측 검사 19개, 검색 계약과 17개 기존 검색 질의 smoke 검사를 통과했다. 새 검사는 정적 탐색의 절대 링크가 실제 생성 파일로 연결되는지, 근거 링크와 미확인 범위가 남는지, 자료명이 HTML로 실행되지 않는지, `공공자전거`로 마스터가 검색되는지를 확인한다. 17개 질의는 통계적 품질 gate의 표본 수를 충족하지 않는다. JavaScript 구문과 비밀정보 스캔도 통과했다. 브라우저의 시각적 레이아웃·클릭 동작을 재검증한 결과는 포함하지 않는다.
