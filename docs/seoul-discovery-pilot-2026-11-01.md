# 서울 POI와 OD 탐색 파일럿 결과

2026년 11월 1일, 서울 지도 과제에 필요한 자료와 도구를 찾는 6개 과제를 세 가지 시작 경로에서 총 18회 실행했다. 현재 정본으로는 **지도 우선 방식의 전반적인 시간·토큰 절감을 확인하지 못했다.** 등록된 지오코딩 후보를 회수하는 경로는 작동했지만, POI·OD 정보원은 정본에 없어서 웹 검색으로 전환했다. 다음 개선의 중심은 정보원 확보, 접근 경로의 검증, 발견과 실행 상태의 구분이다.

## 시험 범위와 조건

| 항목 | 고정 조건 |
|---|---|
| 지도 정본 | `dedb559d257be35d`, 7서비스·16동작·9연결·108근거·정보원 0건 |
| 과제 | 상가 POI, 자전거 OD, ST 식별자와 격자 결합 근거, 좌표변환·공간조인 도구, 지오코딩, 건물별 실측 인원 추론 보류 |
| 조건 | 지도 우선 / 일반 웹 검색 우선 / 지정 공식 디렉터리 메인 우선 |
| 모델 | `gpt-6.1-sol`, medium, 매회 새 CLI 문맥, 조건당 1회 |
| 순서와 시간 | 난수 시드 20261101로 순서 고정, 시행당 900초 제한 |
| 지도 접근 | 공개 정본과 같은 동결 사본을 읽는 시험용 MCP. 네트워크·실행·인증 기능 없음 |
| 공통 도구 | 웹 검색·공식 문서 열람 허용. MCP 스키마는 동일하고 대조 조건의 지도 데이터 접근은 거부 |
| 외부 예산 | 원자 조회 20회로 지시. 실제 준수 여부는 완전히 검증하지 못함 |

디렉터리 조건은 데이터 과제에 서울 열린데이터광장·공공데이터포털, 공간 Python 과제에 PyPI, 지오코딩에 Open-Meteo 메인을 사전 지정했다. 따라서 분야별 시작점에 대한 사전정보가 있는 비교다. 지도 우선 조건은 manifest부터 읽고 분류·검색을 시도하도록 지시했으므로 그 초기 탐색 비용도 포함한다.

각 시행은 이전 답변이나 프로젝트 조사 문서를 읽지 않았다. 18개 문맥 ID의 고유성, 답변 스키마, 기록된 시작 경로, 정본·코드·프롬프트 해시를 검사했다. 대조 조건의 지도 제한은 지시와 기록 감사이며 강제 네트워크 차단은 아니다. 기록에서 지도 노출은 발견되지 않았지만 검색 출력의 모든 우발 노출을 배제하는 보장은 아니다.

처음 시도한 v1에서는 CLI의 파일 읽기 차단으로 지도 자료 접근이 실패했다. v1의 완료 6회와 중단 1회는 진단용으로만 보존하고 이 비교에서 전부 제외했다. v2는 시험용 MCP의 실제 manifest 호출을 확인한 뒤 별도로 잠갔다. 같은 개발 과제를 재실행했으므로 미사용 holdout이라고 볼 수 없다.

토큰은 CLI가 보고한 모델 사용량이며 청구 비용이 아니다. 비캐시 입력은 입력에서 캐시 입력을 뺀 값이다. 실행시간에는 모델 추론·도구 대기·답변 작성이 포함된다. 준비·환경 보정·사후 재확인·외부 AI 검토 비용은 이 표에 포함되지 않으며 파일럿 전체 비용은 계측하지 않았다.

지도 조건은 논리 조회 32회, 어댑터 응답 본문 17,991바이트를 사용했다. 이는 HTTP 트래픽이나 전체 도구 프로토콜 바이트가 아니다. 지오코딩 과제만 최초 발견 경로가 `catalog_hit`였고, 나머지 지도 조건의 후보는 웹 검색으로 발견했다. 따라서 지도 조건에서 T-DATA를 발견한 것을 정본의 기여로 귀속할 수 없다.

등록된 지오코딩 과제의 비캐시 입력은 지도 조건에서 가장 적었다. 다만 웹 조건은 Nominatim, 나머지는 Open-Meteo를 택해 후보·답변 길이가 다르고, 조건당 1회뿐이다. 지도의 인과적 절감 효과나 임계치 통과를 입증하지 않는다. 특히 범위 밖 4개와 부분 범위 1개를 합친 전체값을 등록 자원의 조회 성능으로 해석하면 안 된다.

## 외부 조회 횟수 집계 정정

초기 집계기는 CLI의 완료 이벤트에서 검색 쿼리 수와 대표 동작을 세었다. 그러나 18개 시행 모두에서 다중 URL 열람이나 본문 찾기가 대표 URL 하나 또는 `type=other`로 축약된 사례가 있었다. 대표 동작 수를 원자 요청 수로 쓰면 실제 작업을 적게 센다. 검색 결과 행 수로 바꾸어도 검색 적중 목록과 문서 열람을 정확히 구분할 수 없다.

이에 따라 **20회 조회 예산을 사후 감사로 모두 확인했다는 판정을 철회한다.** 잠긴 원본 집계는 보존하고 별도 정정 감사 파일을 추가했다. 시간·usage·답변·독립 문맥·해시 검사에는 영향이 없다. 다만 동일한 원자 조회 예산을 강제한 통제 실험으로 주장할 수 없으며, 요청 수 절감도 비교하지 않는다. 후속 시험은 도구 호출을 감싸 원래 요청 인자의 모든 query/open/find/click을 실행 전에 계수해야 한다.

## 과제별 근거 검토

아래는 답변 본문, 공식 원문 사후 재확인, 담당 웹 AI 검토를 종합한 정성 판정이다. 90개 required 항목 전체의 독립 정답 채점을 완료했다는 뜻은 아니다. 모델의 `observed=true`나 `found` 표시는 그대로 정답으로 인정하지 않았다.

| 과제 | 확인한 내용 | 남은 제한 |
|---|---|---|
| POI | 세 조건 모두 공식 상가정보 후보와 위치·업종 제공 설명을 찾음. 지도·웹 조건은 파일명상 2026-09-30 기준 자료를 확인 | 원자료 파일·전체 분류표·좌표 품질·자료별 재이용 세부조건 미검증. 디렉터리 조건은 파일 기준일 미확인 |
| OD | 디렉터리는 대여이력, 웹은 5분 OD, 지도 조건의 웹 전환은 T-DATA OD를 찾음 | 서로 다른 후보를 발견했으며 시간 기준·집계 의미·전체 기간을 모두 확인한 조건은 없음 |
| ST 결합 | 세 조건 모두 접미사·이름 유사 매칭을 거부하고 결합 미수행을 명시 | 동일 ID namespace·시점·원좌표 CRS·실제 매칭률을 확보하지 못해 모두 보류 |
| 공간 도구 | 세 조건 모두 pyproj·GeoPandas 공식 문서, 축 순서, 경계점·무매칭 처리 절차를 제시 | 코드·실제 대여소·격자에 대한 변환과 조인은 미실행 |
| 지오코딩 | 세 조건 모두 문서상 후보·이용 조건을 설명. 지도 조건은 정본에서 후보와 binding·인증 근거를 회수 | 시행 내 실응답 열람은 모두 도구 접근 실패. 실제 POI 검색 품질과 OD ID 대응은 미검증 |
| 건물별 실측 인원 | 세 조건 모두 격자 추정치·업종만으로 현재 건물 인원과 개인 목적을 정확히 복원할 수 없다고 보류 | 보류의 타당성과 실제 API 실행 성공은 다른 지표. 인터넷 전체에 해법이 없다는 증명은 아님 |

POI 지도 조건과 OD 일부 조건의 `found`는 공식 후보 발견이라는 의미지만 다른 답변은 비슷한 상태를 `blocked`로 표시했다. 본문은 파일·응답 미확보를 명시했으므로 실제 확보를 거짓 주장했다고 판정하지 않는다. 그러나 이 상태값으로 조건별 성공률을 계산하면 부당하다. 후속 결과 계약은 후보 발견, 문서 검증, 실응답 확인, 작업 완료를 각각 기록하고 접근 실패 사유를 따로 둔다.

## 사후 실제 접근 확인과 새 연결 후보

직접 HTTPS GET으로 [Open-Meteo 지오코딩 문서](https://open-meteo.com/en/docs/geocoding-api)와 무인증 검색 응답을 확인했다. `name=Seoul&count=3&countryCode=KR`는 HTTP 200으로 좌표가 있는 후보 3개를 반환했고, 그중 하나가 Seoul이었다. 나머지는 다른 지역의 유사 지명이다. 이는 한 읽기 전용 서비스에 실제 연결할 수 있음을 보여주며, 모든 서울 POI나 대여소의 검색 정확도를 보증하지 않는다. 시행 중 실패를 사후 성공으로 변경하지 않았다.

[서울시 5분 OD](https://data.seoul.go.kr/dataList/OA-21229/F/1/datasetView.do)는 5일 전 자료 적재와 대여소 마스터 참조를 안내한다. [T-DATA OD 문서](https://t-data.seoul.go.kr/dataprovide/trafficdataviewopenapi.do?data_id=1045)는 ST 형태의 출발·도착 ID를, [운영 대여소 문서](https://t-data.seoul.go.kr/dataprovide/trafficdataviewopenapi.do?data_id=1044)는 ST 형태의 stationId와 위경도를 제공한다. 두 T-DATA 문서의 필드 표와 JSON 예시는 snake_case와 camelCase가 섞여 있어 실제 응답으로 확정해야 한다. 인증키도 요구한다.

이는 앞선 ST 결합 탐색에서 놓친 공식 후보다. 다만 예시 ID가 서로 겹치지 않고, 같은 형식이라는 사실만으로 namespace·유효기간·좌표계의 동일성을 입증하지 않는다. OD 원본과 해당 좌표 레코드를 확보한 뒤 정확 키 결합을 검사해야 한다. 숫자 접미사나 이름 매칭으로 빈틈을 메우지 않는다. 이번에는 서울 OD와 공식 격자의 실제 조인 성공을 확인하지 못했다.

[서울 생활인구 안내](https://data.seoul.go.kr/dataVisual/seoul/seoulLivingPopulation.do)는 250m·시간 단위의 통계적 추정치, 4일 후 공개, 실제 인원과의 차이를 명시한다. 이 한계는 장소 업종을 붙이는 것만으로 해소되지 않는다.

## 웹 AI 검토

BW의 기존 Edge 확장 연결을 사용했고 새 탭이나 창을 만들지 않았다. 동일한 시험 설명과 과제별 세 답변을 보내 담당 범위를 나눴다. 기존 대화 맥락과 모델 설정이 서로 달라 완전한 독립·맹검 평가가 아니며, 누구도 18회를 다시 실행한 것은 아니다.

| 제공자 | 담당 범위 | 확인한 검토 내용 |
|---|---|---|
| ChatGPT | 지오코딩·계측 | 문서상 후보와 실제 응답 차이, 외부 호출 수 불일치, Nominatim 이용정책 검토 필요를 지적 |
| Gemini | POI | 필드·기준일·접근·재이용 검증의 빈틈과 거친 outcome 구분을 지적 |
| Claude | ST 결합 | T-DATA 두 문서와 서울 OD 원문을 재열람. 후보 존재와 동일 namespace·실제 결합을 구분 |
| Perplexity | OD | 후보별 시간·식별자·집계 의미의 미확인, 사후 발견을 시행 성공으로 소급하지 않을 것을 지적 |
| DeepSeek | 좌표변환·조인 | 문서 탐색과 미실행 구분을 수용. 실제 환경의 축 처리·오류 입력 검증을 요구 |
| Grok | 건물 인원 보류 | 요청이 대화에 표시된 것은 확인. 반복 조회와 화면 본문 추가 진단에서도 새 답변이 없어 검토 결과에서 제외 |

Gemini의 “실제 확보를 과장했다”는 표현은 본문의 미확보 명시와 맞지 않아 그대로 수용하지 않았다. 수용한 문제는 `found` 해석의 불일치다. 외부 AI 의견은 공식 근거와 원본 답변에 대조해 채택하며 다수결로 사실을 확정하지 않는다. 원자 조회 집계 정정은 별도 통지하고 최초 검토와 구분해 보존한다.

## 다음 구현과 검증

1. **결과 상태와 계측부터 수정한다.** 발견·문서 검증·실응답·작업 완료를 분리하고, 원자 요청 인자를 계수한다. 최초 유효 후보 시점, 도구 결과 바이트, 모델·도구·프롬프트 해시도 기록한다. 원시 인자를 확보할 수 없는 환경은 요청 수를 미계측으로 표시한다.
2. **정보원을 확보해 검증 가능한 수준으로 등록한다.** 상가 원자료·분류표, 서울 OD, T-DATA OD·대여소 후보, 공식 격자·CRS 문서, pyproj·GeoPandas를 우선 다룬다. 후보·접근 가능·샘플 확인·재이용 조건·결합 미검증을 각각 보존한다. 미확인 값을 채우거나 형식만 같은 ID를 대응표로 등록하지 않는다.
3. **범위 밖 요청을 빠르게 웹으로 넘긴다.** manifest의 범위·분류별 수록 상태로 정본에 없는 분야를 판단하게 해 빈 검색의 반복을 줄인다. 공식 HTML·구조화 메타데이터·직접 API 등 검증된 접근 경로를 기록하되 인증·정책 제한을 우회하지 않는다.
4. **읽기 전용 실제 작업을 별도로 검증한다.** 공개 지오코딩 응답과 공식 데이터의 작은 결합 표본을 분리한다. ST ID·버전·CRS·키 유일성·미매칭·경계점이 확인될 때만 서울 격자 결합을 완료로 표시한다.
5. **등록 후 시험과 일반화 시험을 구분한다.** 같은 과제를 다시 실행하면 등록 회수 회귀로 보고한다. 미사용 표현·다른 자료 계열을 사전에 잠근 별도 과제가 있어야 일반화 평가라고 부른다. 작은 반복 시험에서 효과 크기·변동·오류를 본 뒤 확증 시험 규모를 정한다.

사람 UI는 로컬 브라우저 기능 제한으로 시각 검증하지 못했다. MCP 시험은 동결 정본을 로컬로 읽었으므로 GitHub Pages의 HTTP 지연·캐시·브라우저 사용성 평가도 아니다. R1, 독립 holdout, 통계적 효용 입증과 서울 OD 실제 결합은 남아 있다.
